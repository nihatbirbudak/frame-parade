# Working with Frame Parade

This repository is a configurable video-production kit. Its owner supplies the channel, material and decisions. Use the owner's language in conversation; project documentation is primarily English.

## Start here

- For a new setup, read KURULUM.md, KURALLAR.md and LICENSE.
- Ask the setup questions in kurulum/questions.md or kurulum/sorular.md one topic at a time. Reuse answers already given.
- Runtime settings belong in existing kanal.json fields. Human preferences belong in yonetim/VIDEO-KIMLIGI.md, yonetim/referanslar.md and yonetim/ROLLER.md.
- Use actual files and command results as evidence. Do not claim installation, rendering, audio quality or publishing succeeded without the corresponding result.

## Roles and production

Record who writes, produces, reviews and approves in yonetim/ROLLER.md. Follow the owner's assignments. By default, the same model writes and produces sequentially, with the owner reviewing the result. Add a second model only when the owner chooses it; agent-post is optional. Extra roles do not automatically require more sessions or services.

For each video:

1. Establish the topic, intended viewer and concrete benefit.
2. Prepare the title, opening and script. Verify facts and calculations.
3. Turn the approved text into scenes and review the design separately.
4. Produce a small local preview, then inspect the finished output using KALITE-KAPISI.md.
5. Prepare the complete delivery package and use the owner's applicable publishing authorization.

Use the actual tools under kalite/ and ses/ for evidence. Their scope and limitations are listed in KALITE-KAPISI.md. A clean console report is not a substitute for inspecting the video. Ask the owner to listen before accepting a new voice or effect.

The initial setup produces a local silent portrait sample. Optional services can stay unconfigured. Follow LICENSE and preserve third-party rights.

## Decisions and continuation

Record material decisions in yonetim/karar-gunlugu.md: date, decision, rationale and who decided. Use its K-001 numbering format; check the last entry before adding a number. Respect any assigned ownership of the log. Measure the current date and time when recording them.

Keep a short continuation note in the project's management records: completed work, actual output paths, checks, unresolved issues and next step. Distinguish owner decisions, agent recommendations and unverified reports. Never include secrets.

## Boundaries

Follow KURALLAR.md for source files, credentials, spending, account access and publishing. Use a dedicated headless browser for rendering; do not control or record the owner's desktop.

Existing authorization remains valid within its stated scope. Do not ask for it repeatedly. If an essential decision is missing, continue independent preparation and ask only for that decision.

If code and documentation disagree, identify the exact mismatch, report its effect and resolve it before relying on that step.
